## Motivation and inputs

Mesen's source-to-edge-latch CPU counter delta is 0; native's is +1; native's first post-edge poll promotes pending NMI immediately and no ordinary opcode fetch occurs after the edge latch before the first discarded NMI fetch. ## Source-grounded physical clock strategy

- Mesen2 pinned `SourMesen/Mesen2@b9fa69ddc6d0a331fb103fdb5eef6904305703c2`: `NesPpu<T>::Run` calls `Exec()` *before* incrementing the PPU `_masterClock` by its divider. At `NesPpu<T>::TriggerNmi()`, log the **actual** PPU `_masterClock` and scanline/dot rather than JP0678's hardcoded `master=0` placeholder. The corresponding CPU-coordinate PPU event is `ppu._masterClock + cpu._ppuOffset`. At `NesCpu::EndCpuCycle`, log `_masterClock` and `_state.CycleCount` when the NMI signal is detected. Log eligibility and acceptance with the same read-only CPU master-clock convention.
- NESRecomp pinned `mstan/nesrecomp@2b4fcdb98c9e702be3fb365cfc645003c50b5fc1`: master time is `12*hw.cycles + actual_scheduler_tick` in the NTSC diagnostic. `hw.tick` **alone is not safe** in the optimized unrolled `run_ticks_1_to_11` code; the probe sets a read-only `jp0683_actual_tick` at each subcycle in every case (0–3) while preserving the order of all `ppu_dot`, `ppu_half_dot`, `sample_nmi` and IRQ sample calls. Its CPU NMI sample is always tick 4. Add a distinct bus-access-site `FETCH_ACCESS` event, because JP0680's `FETCH_PROCEED` is logged *after* `hw_cycle_finish()` and is not an actual opcode-bus timestamp. Continue to verify the separate JP0676 complete-instruction evidence.
- **No master-clock origin equivalence is assumed:** align interval measurements to each engine's own `PPU_ASSERT` at scanline 241, dot 1; compare *within-engine* source-to-edge timings measured in 12-tick NTSC master-clock units. Identical PPU coordinates do not independently prove either emulator models physical silicon phase perfectly, nor that original Mesen's own CPU-cycle counter convention equals rebuilt Mesen's.
- These master events cannot certify native-vs-original exact interrupt behavior without matching final instruction-cycle acceptance boundaries and checking hardware behavior. No CPU/PPU timing patch is authorized automatically.
